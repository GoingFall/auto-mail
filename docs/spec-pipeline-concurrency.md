# 规格七：主流程编排与并发安全

> 对应实现 `src/automail/pipeline.py` 与命令 `automail run`。

## 1. 阶段编排

```
sync → extract → push → mark-read [→ digest]
```

每个阶段独立成败，**任一阶段失败不阻止后续阶段**。

`mark-read` 的位置是有约束的：必须在 extract 与 push **之后**。判定
「该邮件已处理完」依赖抽取结果与事件状态，跑在前面就会用上一轮的旧状态
做决定——而那是一个**会改变邮箱状态**的操作，判错会让需要处理的邮件
从「未读」里消失。

未开启（``MARK_READ_POLICY=off``，默认）时该阶段**明确报告跳过**，而不是
静默什么都不做：静默会被误认为功能故障，而这是配置问题、应当可诊断。

``digest`` 仍在最后，因为它要呈现本轮全部结果。

## 2. 为什么阶段之间互不阻塞

这是刻意的设计，不是"偷懒"。考虑真实的使用形态：

| 情况 | 若阶段间阻塞 | 实际行为（本设计） |
|---|---|---|
| 邮箱风控断开 | 整轮失败，本地 89 封已同步邮件得不到抽取 | 同步记为部分完成，**抽取照常** |
| LLM 未配置 | 抽取失败，已批准事件推不出去 | 抽取降级为仅规则，**推送照常** |
| 日历 API 限流 | 推送失败，且下次启动可能又卡在同步 | 推送记为部分完成，**下次重试** |
| 缺邮箱凭据 | 整轮失败，使用者无法在本地重跑 | **跳过同步**，其余照常 |

最后一条尤其重要：使用者经常只想「在本地重跑抽取」或「重试推送」，
此时没有邮箱凭据（或不想连邮箱）是完全正常的。

## 3. 退出码语义

| 码 | 含义 | 典型场景 |
|---|---|---|
| 0 | 全部阶段成功 | 正常运行 |
| 1 | 部分完成 | 缺凭据跳过、LLM 降级、推送失败、检测到手改而冻结 |
| 2 | 致命 | 认证失败（凭据错了，继续无意义） |

整体取**最严重**的阶段。两个关键判断：

* **网络/风控失败 = 1 而非 2**：下次运行会重试，把它当致命会让计划任务
  反复告警，而实际只是临时故障。
* **冻结 = 1**：检测到用户手改而停止写入是**正确行为**，但需要人处理，
  因此不能报成功而无提示。

## 4. 并发安全：两层防线 ★

### 4.1 第一层：TTL 单实例锁

`locks` 表 + `owner_run_id` + TTL 抢占。用途是**减少无谓工作**：

* 两个任务同时同步同一邮箱 → 多一次无谓的邮箱往返（163 有风控，能少连更好）
* 两个任务同时推送 → 多一次日历 API 调用（有配额）

**拿不到锁不是错误**：那说明上一次运行还在进行，属正常重叠调度，
退出码为 1。

### 4.2 为什么用数据库锁而不是文件锁

| | 数据库锁 | 文件锁 |
|---|---|---|
| 崩溃后残留 | **TTL 后自动失效**，无需人工清理 | 残留文件永久阻塞，需手动删除 |
| 与事务关系 | 同库同事务，一致性强 | 与数据状态无关联 |
| 内容 | 含 owner 与到期时间，可诊断 | 通常只有一个 PID |

实测验证：模拟崩溃留下的锁，在新运行时被自动接管；
`purge_expired()` 也能主动清理。

### 4.3 第二层：幂等性（真正保证正确性）

**锁不是正确性的单点依赖。** 锁的粒度只覆盖单次 `Pipeline.run()`——若两个
任务几乎同时启动，第二个可能在第一个释放锁后才拿到锁，此时锁形同虚设。

但这不会造成损害，因为下层的幂等性顶住了：

| 层 | 幂等机制 |
|---|---|
| 同步 | `highest_uid` 游标 + `UNIQUE(account, folder, uid_validity, uid)` |
| 抽取 | `UNIQUE(message_id, fingerprint)` |
| 推送 | create 前按 `auto_mail_key` 反查，命中则**回填**而非新建 |
| 摘要 | 同一天写同一文件（`digest-YYYY-MM-DD.md`） |

**已实测验证**：两个运行重叠时，第二个的 `created=0`（识别出远端已有该事件），
日历里仍只有 1 个事件。

### 4.4 分层的意义

```
锁（减少无谓工作）  →  幂等性（保证正确）
     第一道                   第二道
```

这个分层让系统在**任一机制失效时依然安全**。测试里专门覆盖了
「锁失效时幂等性顶住」这条路径（`test_idempotency_holds_when_runs_overlap`）。

## 5. 摘要的幂等键

摘要按**本地日期**命名（`digest-2026-09-14.md`），同一天重复生成会覆盖同一
文件，不产生 `digest-2026-09-14-2.md`。

日期用 `USER_TIMEZONE` 换算，不是 UTC——否则在 UTC+8 的晚上 8 点后生成，
会被写成"明天"的文件。

## 6. 跳过选项

```
run --no-sync     只处理本地已有邮件（不连邮箱）
run --no-extract  只同步与推送
run --no-push     只同步与抽取
run --digest      末尾生成摘要
```

`--no-sync` 是最常用的：163 有风控，能少连一次就少一次。

## 7. 测试覆盖

`tests/test_pipeline.py` 覆盖：锁的独占/重入/过期接管/异常路径释放、
被拒时不执行任何阶段、sync 的四种失败分类（缺凭据跳过、认证致命、
网络部分、风控部分）、extract 降级、push 冻结与失败、digest 失败不阻断、
退出码取最严重、跳过选项、dry-run 零副作用、**锁失效时幂等性顶住**、
`SyncStats` 聚合完整性（`scanned` 缺失曾导致「扫描 0，新增 1」的矛盾显示）。
